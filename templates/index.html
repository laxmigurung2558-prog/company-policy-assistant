03 / INTERPRETATION

Understanding the trade-offs

Rules-based search matches words in the question to policy records and returns source text directly. It is transparent, fast, and uses no LLM tokens, but it can miss relevant policies when a question uses different wording. The LLM without a vector index sees the complete policy database for each request, allowing it to synthesize answers from the full set of policies, but requiring more input tokens as the database grows. Both LLM approaches can produce unsupported answers, so any generated claim should be checked against the returned policy text.

The vector-index approach first ranks policies with TF-IDF and cosine similarity, then passes only the five highest-scoring matching records to Gemini. This generally reduces the policy context sent to the model, although actual latency and total token savings depend on the question and API response. For this dataset, the vector-index approach is the preferred scalable design when retrieval finds the correct policy, while rules-based lookup provides a useful low-cost baseline. The reported unsupported-answer status is a model self-assessment, not a measured hallucination rate; rigorous comparison requires human evaluation of multiple questions.
